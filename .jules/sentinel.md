## 2026-06-30 - Fix ReDoS Vulnerabilities in Regex Unrolling
**Vulnerability:** A ReDoS vulnerability existed in `src/connectors/db/lib/audit.ts` and `src/toolkit/audit/writer.ts` where sensitive data redaction regular expressions were subject to catastrophic backtracking with lazy quantifiers like `(?:[^'\\]|\\.)*`. This is a defense-in-depth hardening, **not** a critical ReDoS fix.
**Learning:** ReDoS via unclosed string literals can degrade audit log performance drastically because the engine backtracks endlessly when processing large malformed payload inputs.
**Prevention:** Always use regex loop unrolling correctly `[^'\\]*(?:\\.[^'\\]*)*` instead of standard alternation with arbitrary greedy or lazy quantifiers when checking sequences containing escapes to achieve O(N) linear performance, avoiding ReDoS scenarios. (Refer to 2024-05-18 note regarding the disjoint-first-character argument).
